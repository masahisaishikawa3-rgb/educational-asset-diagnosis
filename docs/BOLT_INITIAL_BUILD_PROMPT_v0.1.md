# Bolt.new用｜教育資産化診断 初回構築プロンプト v0.1

以下のプロンプト本文を、`docs/codex-handoff/` の6ファイルと一緒にBolt.newへ渡してください。

---

## プロンプト本文

あなたはB2Bマーケティング向けWebアプリの実装担当です。

添付された6つの引き渡し資料を正本として、「教育資産化診断」の初回版を構築してください。

### 参照資料と優先順位

1. `01_PROJECT_REQUIREMENTS.md`
2. `02_SCREEN_FLOW_AND_COPY.md`
3. `03_DIAGNOSIS_RULES_AND_CONTENT.md`
4. `04_UI_UX_DESIGN_RULES.md`
5. `05_IMPLEMENTATION_ANALYTICS_AND_STATES.md`
6. `06_OPEN_ISSUES_AND_ACCEPTANCE_CHECKLIST.md`

資料間に解釈差がある場合は、元の実装仕様書とUI設計書に近い、変更の少ない解釈を採用してください。判断できない事項を推測で確定せず、設定値または未接続状態として分離してください。質問、選択肢、Level結果文、Type結果文は勝手に要約・改変しないでください。

### 今回のゴール

まず、診断開始から結果表示までを一通り操作できるフロントエンドを完成させてください。

- Landingから診断を開始できる
- 12問を1画面1問で回答できる
- 戻る／次へで回答が保持される
- 未回答では次へ進めない
- 最終問から結果を表示できる
- 4軸、総合Level、最大ボトルネックTypeを仕様どおり計算できる
- Level結果文、Type結果文、最初に取り組む3つを切り替えられる
- 推奨記事カードとCTAを所定の順序で表示できる
- デスクトップとモバイルの両方で利用できる
- 主要ロジックをテストできる

### 技術方針

- React + TypeScriptで構築してください。
- 診断データと判定ロジックをUIコンポーネントから分離してください。
- 質問、選択肢、配点、Level閾値・名称・結果文、Type名称・結果文、推奨記事、CTA URL、アプリバージョンは設定ファイルで変更できるようにしてください。
- 回答状態は、初回版ではsessionStorageを使用してください。
- URLに回答やスコアを含めないでください。
- DB保存を結果表示の前提にしないでください。
- analyticsと匿名保存は、画面を止めないアダプター／抽象化として用意してください。
- 外部サービスの認証情報や秘密鍵は追加しないでください。

### 画面構成

以下の順序を維持してください。

1. Landing
2. 12問のQuestion flow
3. Result Hero: Level＝現在地
4. 最大ボトルネック: Type
5. 判定根拠: 4軸の横棒グラフ
6. 処方箋: 最初に取り組む3つ
7. 推奨記事
8. 自社資料で試すPrimary CTA
9. 教育資産化について詳しく読むSecondary CTA

結果画面でCTAを上部へ移動しないでください。結果価値を十分に提示した後で、初めてコンテキストAIへの導線を表示してください。

### 診断ロジック

`03_DIAGNOSIS_RULES_AND_CONTENT.md` の12問、回答、配点、Level判定、Type判定をそのまま使用してください。

- 各問1〜4点
- 各軸3〜12点
- 総合12〜48点
- Level閾値は設定ファイルから変更可能にする
- 最低点の軸を最大ボトルネックとする
- 最低点が同点の場合は A → B → C → D の順でprimary typeを決める
- 同点のsecondary weak typeも保持し、結果画面で同程度の改善余地があることを補足できる構造にする

画面上では回答点を表示しないでください。総合点を表示する場合も補足情報に留め、Level、Type、次のアクションより強く見せないでください。

### デザイン方針

- 落ち着いたB2Bの現在地確認ツールとして設計する
- 白〜淡いオフホワイト背景
- 黒〜濃紺／グラファイト系の本文
- アクセントは1色
- グラデーションを使わない
- ゲーム的な演出を使わない
- 過度にカードを並べない
- 低スコアを赤・黄・緑で評価しない
- レーダーチャートではなく横棒グラフを使う
- Level数字だけを極端に大きくしない
- 本文は16px前後を基準にし、補助文字も小さくしすぎない
- デスクトップは最大幅720〜860px程度
- Questionは中央1カラム
- モバイルは完全1カラム、CTAは横幅100%
- モバイルで1画面に収めるために文字を小さくしない

回答選択肢はカード全体をクリック可能にしてください。ただし、回答選択直後に自動遷移せず、「次へ」を押して進む仕様にしてください。

### 初回版で未接続にするもの

以下は未決事項です。架空のURLや仕様を作らないでください。

- 推奨記事の正式URL
- Primary CTAの正式URL
- Secondary CTAの正式URL
- GA4測定ID
- Supabase接続情報
- 正式なブランドカラー、ロゴ、フォント
- 公開ドメイン

未確定URLは設定ファイルで空値にし、UIは開発用の無効状態または明確なプレースホルダー状態を扱えるようにしてください。推奨記事名は仕様書記載の候補だけを仮データとして使用し、`status: "candidate"` などで確定データと区別してください。

匿名結果保存は初回版では有効化しないでください。ただし、将来有効化できるインターフェースだけ用意し、保存失敗で結果表示を止めない構造にしてください。コンテキストAI本体のDBには接続しないでください。

### Analytics

GA4を直接初期化する代わりに、以下のイベントを呼び出せるanalyticsアダプターを用意してください。測定IDがない状態でもエラーにせず、診断を完了できるようにしてください。

- `diagnosis_view`
- `diagnosis_start`
- `diagnosis_answer`
- `diagnosis_complete`
- `diagnosis_recommendation_click`
- `diagnosis_primary_cta_click`
- `diagnosis_secondary_cta_click`

イベント名とパラメータは `05_IMPLEMENTATION_ANALYTICS_AND_STATES.md` に従ってください。

### エラーと状態

- 設定読込エラーと結果計算エラーには、再試行または最初からやり直す導線を用意する
- analyticsエラーや匿名保存エラーでは画面を停止しない
- 回答途中のリロードではsessionStorageから回答を復元する
- 結果に必要な回答がない状態でResultへ直接アクセスした場合は、推測で結果を作らずLandingまたは診断開始へ案内する
- Primary CTA URLが空の場合の状態を実装する

### テスト

診断ロジックのユニットテストを追加してください。最低限、以下を確認してください。

- 全回答1点 → Level 1
- 全回答4点 → Level 5
- Aのみ最低、Bのみ最低、Cのみ最低、Dのみ最低
- A/B同点時にAがprimary
- B/C同点時にBがprimary
- Level境界: 19/20、27/28、35/36、42/43
- 戻る／進むで回答を保持
- 未回答では次へ進めない
- analyticsや保存処理の失敗で結果表示が止まらない

### 今回作らないもの

- ログイン／アカウント登録
- 自由記述診断またはLLM診断
- PDF／Word／PowerPointアップロード
- PDF結果出力
- メール送信
- CRM連携
- 複雑なAIレコメンド
- コンテキストAI本体DBとの接続
- 有料契約処理
- 企業規模／業種の必須質問

### 完了時に提示するもの

実装完了後、以下を簡潔に報告してください。

1. 作成した画面と主要コンポーネント
2. 診断設定・判定ロジックの配置場所
3. 実行したテストと結果
4. 未接続の設定値と差し替え場所
5. 元仕様から判断できず保留した事項

元仕様の内容を変更したり、未決事項を独自判断で確定したりしないでください。

- 匿名保存: 無効
- 記事・CTA URL: 空値／未接続
