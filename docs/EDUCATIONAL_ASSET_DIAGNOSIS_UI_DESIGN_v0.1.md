# 教育資産化診断｜画面・情報設計 v0.1

## 0. 位置づけ

本書は `EDUCATIONAL_ASSET_DIAGNOSIS_SPEC_v0.1.md` の前段となるUI/UX設計書。
目的は、Bolt.new等で実装する際に「どの情報を、どの順番で、どの強さで見せるか」を固定すること。

市場形成ファネル上の役割：
**④ 概念獲得 → ⑤ 自社化 → ⑥ 解決理解**

---

# 1. 全体体験

```text
[流入]
ブログ / 教育資産化とは / SNS / PR / セミナー
   ↓
[01 Landing]
教育資産化診断とは何か
   ↓
[02-13 Questions]
12問 / 約3分
   ↓
[14 Result Hero]
教育資産化Level
   ↓
[15 Diagnosis Detail]
4軸 + 最大ボトルネック
   ↓
[16 Prescription]
最初に取り組む3つ
   ↓
[17 Recommended Content]
あなたへの推奨記事
   ↓
[18 Next Action]
自社資料で試す / 教育資産化を詳しく読む
```

設計原則：
- 「診断される」より「自社の現在地を整理する」感覚
- 診断完了まで個人情報入力なし
- 結果を見せてから初めて製品導線を置く
- 低スコアを赤くしない
- 総合点より「現在地」「最大ボトルネック」「次の一歩」を優先
- コンテキストAIの機能説明は診断中には出さない

# 3. 画面02〜13｜質問

## 目的
迷わず回答させる。同時に、回答行為そのものを市場教育にする。

## ワイヤー

```text
┌────────────────────────────────────────────┐
│ 教育資産化診断                       4 / 12 │
│ ████████████░░░░░░░░░░                     │
│                                            │
│ B. 教材化                                  │
│                                            │
│ 社内資料を従業員教育に                     │
│ どのように使っていますか？                 │
│                                            │
│ ○ ほとんど活用していない                   │
│ ○ PDFやPowerPointなどをそのまま共有        │
│ ○ 担当者が研修用に加工している             │
│ ● 学習目標や理解の順序を考えて教材化       │
│                                            │
│ [ 戻る ]                         [ 次へ ]   │
└────────────────────────────────────────────┘
```

## UIルール
- デスクトップでも本文幅は広げすぎない
- 選択肢全体をクリック可能なカードにする
- 1〜4点はユーザーに見せない
- 「良い回答」「悪い回答」を色で示さない
- 進捗バー + `4 / 12`
- 軸名（A〜D）は小さく表示してよい
- 回答選択後に自動遷移しない。誤タップ防止のため「次へ」を押す
- 前問に戻って変更可能

## モバイル
- 選択肢は縦積み
- 下部CTAをstickyにしてもよい
- 1画面に質問と4回答が収まらなくてもよい。文字サイズを削らない

# 4. 画面14｜結果Hero

## 目的
3秒で「自社の現在地」を理解させる。

## ワイヤー

```text
┌────────────────────────────────────────────┐
│ 診断結果                                   │
│                                            │
│ 御社の教育資産化レベル                     │
│                                            │
│              LEVEL 2                       │
│            資料蓄積型                       │
│                                            │
│ 社内知識は資料として残り始めています。     │
│ 次は、それを「社員が学べる形」へ変える     │
│ ことが重要です。                           │
│                                            │
│       ↓ もう少し詳しく見る                 │
└────────────────────────────────────────────┘
```

## 重要
**48点中○点を主役にしない。**

点数を出す場合も補足情報に留める。
主役は `LEVEL + 名称 + 一言説明`。

理由：
- 点数は競争・評価の印象を作る
- 市場形成では「現在地を理解する」方が重要
- Levelという共通言語を市場に育てたい

# 5. 画面15｜4軸 + ボトルネック

## 目的
「なぜこの結果なのか」と「どこを優先すべきか」を納得させる。

## 推奨表示
レーダーチャートではなく**横棒グラフ**を採用。

```text
教育資産化の4つの状態

知識の体系化   █████████░░░  9 / 12
教材化         █████░░░░░░░  5 / 12
運用・活用     ████████░░░░  8 / 12
測定・改善     ███████░░░░░  7 / 12
```

### ボトルネックカード

```text
┌────────────────────────────────────────────┐
│ 現在の最大ボトルネック                     │
│                                            │
│        「教材化」                           │
│                                            │
│ 社内資料を「学べる形」に変える工程に       │
│ 改善余地があります。                       │
│                                            │
│ 資料を増やすことより、すでにある資料に     │
│ 学習目標・理解順序・説明・確認を加える      │
│ ことが優先です。                           │
└────────────────────────────────────────────┘
```

## 同点時
例：
「教材化」と「運用・活用」が同点の場合、

> 現在の最大ボトルネックは「教材化」です。「運用・活用」にも同程度の改善余地があります。

と補足する。

# 6. 画面16｜処方箋

## 目的
診断を「なるほど」で終わらせず、行動可能な状態へ進める。

## ワイヤー

```text
まず取り組む3つ

01  教材化する社内資料を1つ選ぶ
    最初から全社資料を対象にせず、
    教育上重要な1資料から始めます。

02  「何を学ばせるか」を定義する
    資料の要約ではなく、受講後に
    何ができる状態を目指すかを決めます。

03  説明・具体例・理解確認を加える
    「読む資料」から「学べる教材」へ
    変換します。
```

## UI
- 3項目以上に増やさない
- 一項目につき見出し + 1〜2文
- 「改善してください」ではなく「最初にやること」
- コンテキストAIの機能名を混ぜない

# 7. 画面17｜推奨コンテンツ

## 目的
既存ブログを「処方箋」として再利用し、⑥解決理解を深める。

## 見出し
**今の御社におすすめの記事**

## カード構造

```text
┌────────────────────────────────────────────┐
│ 5 min read                                 │
│                                            │
│ 社内資料は、なぜそのままでは               │
│ 教材にならないのか                         │
│                                            │
│ 資料と教材の違いを、教育設計の観点から     │
│ 整理します。                               │
│                                            │
│                              記事を読む →  │
└────────────────────────────────────────────┘
```

## ルール
- 2本を基本、最大3本
- 「人気記事」ではなく診断結果に合う記事
- 記事タイトルだけでなく「なぜ今読むのか」を1行添える
- 外部遷移でも診断結果を失わないよう、同一タブ/別タブはUX検証で決める
- GA4で記事クリックを計測

# 9. 結果画面の情報優先順位

結果画面はこの順序を崩さない。

1. **Level：現在地**
2. **Type：最大ボトルネック**
3. **4軸：判定根拠**
4. **処方箋：次の3アクション**
5. **推奨記事：理解を深める**
6. **1資料デモ：実際に体験する**
7. **教育資産化とは：概念へ戻る**

マーケティング上はCTAを上に置きたくなるが、
v0.1では診断価値を十分提供してからCTAを出す。

# 10. デザイン方向

## 基本
- 白〜淡いオフホワイト背景
- 黒〜濃紺/グラファイト系の本文
- アクセントは1色
- グラデーション不要
- 過度なカード乱用を避ける
- ゲーミフィケーション不要
- 「健康診断」「企業成熟度診断」に近い落ち着いた体験

## 文字
- H1：大きいが誇張しない
- 本文：16px前後を基準
- 補助テキストも小さくしすぎない
- Level数字だけ極端に巨大化させない

## スコア
- 赤・黄・緑で優劣を表現しない
- 同一アクセント色の濃淡か、無彩色 + 1色
- accessibilityを優先

# 11. レスポンシブ

## Desktop
- 最大幅 720〜860px程度
- Questionは中央1カラム
- Resultは必要に応じて2カラム可
  - 左：Level/Type
  - 右：4軸

## Mobile
- 完全1カラム
- CTAは横幅100%
- 横棒グラフはラベルを上、バーを下にしてもよい
- 結果ページを長くしてよい。情報を削らない

# 12. 状態設計

最低限必要な状態：

### Landing
- default

### Question
- unanswered
- answered
- previous answer restored

### Result
- calculated
- recommendation links available
- primary CTA unavailable（遷移先未確定時の開発用）

### Error
- diagnosis config load error
- result calculation error
- analytics errorは画面を止めない
- DB保存エラーは結果表示を止めない

v0.1はfail-open。
診断結果の表示を、GA4や匿名保存の失敗で妨げない。

# 16. v0.1デザインレビューで見るポイント

1. 「診断アプリ」ではなく「B2Bの現在地確認」に見えるか
2. LandingからコンテキストAI臭が出すぎていないか
3. 12問を答える心理的負担が低いか
4. Levelが評価・序列ではなく現在地として読めるか
5. ボトルネックの納得感が最も強く見えるか
6. 結果画面が営業ページ化していないか
7. 推奨記事が処方箋として機能しているか
8. 最後のCTAで初めて製品へつながる構造になっているか
9. モバイルでも本文が読みやすいか
10. 低スコアが「悪い会社」という印象を与えないか
