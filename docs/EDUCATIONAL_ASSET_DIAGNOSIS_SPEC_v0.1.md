# 教育資産化診断アプリ 実装仕様 v0.1

## 0. 文書の位置づけ
本書は、「教育資産化診断」を独立Webアプリとして実装するためのv0.1仕様書。
市場形成戦略上の役割は、8段階ファネルの **④概念獲得 → ⑤自社化 → ⑥解決理解** をつなぐこと。
コンテキストAI本体には組み込まず、マーケティング用の独立アプリとして構築する。

### v0.1の目的
- 企業担当者が、自社の教育資産化の現在地を2〜3分で把握できる
- 自社の最大ボトルネックを理解できる
- 次に読むべき既存コンテンツ／取るべきアクションが分かる
- 1資料デモ／コンテキストAI体験への自然な導線を作る
- 診断完了率、結果傾向、CTAクリックを計測できる

### v0.1でやらないこと
- ログイン／アカウント登録
- LLMによる自由記述診断
- PDF／Word／PowerPointアップロード
- CRM連携
- メール配信自動化
- 複雑なAIレコメンド
- コンテキストAI本体DBとの接続
- 診断結果を有料契約に直接結びつける処理

# 1. プロダクトコンセプト
## 名称
**教育資産化診断**

### サブコピー候補
御社の社内知識は、「教育資産」として活用できていますか？

### 補足
12問・約3分で、教育資産化の現在地とボトルネックを確認できます。

# 2. 想定ユーザー
- 人事／人材開発
- 研修担当
- 教育企画担当
- 管理部門
- 現場教育の責任者
- 中小〜中堅企業の経営者

診断時点では、コンテキストAIを知らないユーザーも含む。

# 3. UX原則
1. 診断結果を見るまで個人情報を要求しない
2. 1画面あたり1問を基本とする
3. 回答自体が「教育資産化とは何か」を学ぶ体験になる
4. 点数競争にしない
5. 「弱い会社」と評価する表現を避ける
6. 総合点より「現在地」と「次の優先課題」を重視する
7. コンテキストAIの営業導線は結果提示後に出す
8. 結果はルールベースで説明可能にする

# 6. 質問・回答
各回答を1〜4点で採点する。

## A. 知識の体系化
### Q1
従業員に「何を身につけてもらう必要があるか」が整理されていますか？
1. ほとんど整理されていない
2. 部分的には整理されている
3. 主な業務について整理されている
4. 体系的に整理され、定期的に見直している

### Q2
業務に必要な知識やノウハウは、どのような状態ですか？
1. 主に担当者・熟練者の頭の中にある
2. 資料と人の記憶に分散している
3. 社内資料として概ね残っている
4. 必要な知識が整理され、必要な人が参照できる

### Q3
新人・経験者・職種などによって、必要な学習内容を整理できていますか？
1. ほぼ同じ教育をしている
2. 担当者の判断で変えている
3. 一部で対象者別に整理している
4. 対象者ごとの学習目標・内容が明確になっている

## B. 教材化
### Q4
社内資料を従業員教育にどのように使っていますか？
1. ほとんど活用していない
2. PDFやPowerPointなどをそのまま共有している
3. 担当者が研修用に加工している
4. 学習目標や理解の順序を考えて教材化している

### Q5
教材を作る際、「何を・どの順番で・どう教えるか」を設計していますか？
1. ほとんど設計していない
2. 作成者の経験に任せている
3. 一部にルールやテンプレートがある
4. 学習目標から一貫して設計している

### Q6
熟練者や担当者が持つ判断・コツ・経験を教材に反映できていますか？
1. ほとんどできていない
2. OJTや口頭説明に依存している
3. 一部をマニュアル・教材化している
4. 継続的に収集し、教材へ反映している

## C. 運用・活用
### Q7
教材や研修内容は、どの程度更新されていますか？
1. 更新時期が決まっていない
2. 問題が起きたときに更新する
3. 定期的に見直している
4. 業務・制度・製品の変更に合わせ継続的に更新している

### Q8
教育コンテンツの作成・更新は特定の担当者に依存していますか？
1. 強く依存している
2. かなり依存している
3. 複数人で対応できる
4. 標準化されたプロセスで運用できる

### Q9
必要な従業員へ、必要な教育を適切に届けられていますか？
1. ほとんど管理できていない
2. メールやファイル共有などで配布している
3. 対象者を決めて受講管理している
4. 対象者・進捗まで継続的に管理している

## D. 測定・改善
### Q10
誰がどの教育を受講したか把握できますか？
1. 把握できない
2. 一部のみ把握している
3. 概ね把握できる
4. 組織的に管理できる

### Q11
従業員が内容を理解したか確認していますか？
1. 確認していない
2. アンケートや感想を中心に確認している
3. テストなどで理解度を確認している
4. 理解度を継続的に確認している

### Q12
受講結果を、教材や教育方法の改善に使っていますか？
1. ほとんど使っていない
2. 問題があったときだけ見直す
3. 定期的に改善している
4. 結果をもとに継続的な改善サイクルを回している

# 7. スコアリング
各問1〜4点。
各軸3〜12点。総合12〜48点。

## 7.1 Level判定
- Level 1｜属人型: 12〜19点
- Level 2｜資料蓄積型: 20〜27点
- Level 3｜教材化型: 28〜35点
- Level 4｜運用型: 36〜42点
- Level 5｜教育資産型: 43〜48点

上記閾値は初期仮説。公開前後の分布を見て調整可能にする。閾値・文言はconfig化する。

## 7.2 Type判定
4軸のうち最も低いスコアを最大ボトルネックとする。
- A最低 → 体系化不足型
- B最低 → 教材化不足型
- C最低 → 運用不足型
- D最低 → 改善不足型

### 同点時
v0.1は A → B → C → D の順でprimary typeを決定する。
ただし結果文では、同点のsecondary weak typeも補足できるようにする。

# 8. Level結果文
## Level 1｜属人型
社内の知識や教育が、担当者・熟練者・OJTに強く依存している段階です。まずは「何を教える必要があるか」と「どこに知識があるか」を整理することが、教育資産化の第一歩になります。

## Level 2｜資料蓄積型
社内知識は資料として残り始めています。一方、資料を保存・共有することと、社員が学べることは同じではありません。既存資料を学習目標・順序・説明・確認まで含む教材へ変えていくことが次のテーマです。

## Level 3｜教材化型
教育に使えるコンテンツが整い始めています。次は、対象者への配信、更新、担当者間の運用を仕組みにして、継続的に活用できる状態へ進めることが重要です。

## Level 4｜運用型
教育の制作・配信・管理が一定の仕組みとして回っています。次は、受講状況や理解度を改善につなげ、教育そのものが継続的に育つ状態を目指す段階です。

## Level 5｜教育資産型
社内知識を教材化し、配信・活用・測定・改善へつなげる基盤が整っています。今後は、対象者別の最適化や知識更新の速度、教育効果との接続など、教育資産の価値をさらに高めていく段階です。

# 9. Type結果文
## 体系化不足型
**見出し**: 教えるべき知識の整理が、現在のボトルネックです。

**説明**: 教育を増やす前に、「誰に、何を身につけてもらう必要があるのか」と、必要な知識がどこに存在するのかを整理することが優先です。

**最初に取り組む3つ**
1. 教育対象となる業務・テーマを1つ選ぶ
2. 必要な知識・判断・手順を洗い出す
3. 対象者ごとの到達点を決める

## 教材化不足型
**見出し**: 社内資料を「学べる形」に変える工程が、現在のボトルネックです。

**説明**: 資料を保存・共有するだけでは、社員が理解し、判断や行動へ生かせるとは限りません。「何を・どの順番で・どう教えるか」という教育設計を加えることが優先です。

**最初に取り組む3つ**
1. 教材化する社内資料を1つ選ぶ
2. その資料から「何を学ばせるか」を定義する
3. 説明・具体例・理解確認を含む教材へ変換する

## 運用不足型
**見出し**: 教育を継続的に回す仕組みが、現在のボトルネックです。

**説明**: 教材があっても、更新や配信が担当者任せでは教育資産として活用し続けることが難しくなります。制作・更新・配信の運用ルールを整えることが優先です。

**最初に取り組む3つ**
1. 教材ごとの管理責任を明確にする
2. 更新のタイミング・ルールを決める
3. 誰に何を届けるかを継続的に管理する

## 改善不足型
**見出し**: 受講結果を教育改善へ戻す仕組みが、現在のボトルネックです。

**説明**: 「受講した」で終わらず、理解できたか、どこでつまずいたかを把握することで、教育資産は継続的に価値を高められます。

**最初に取り組む3つ**
1. 受講状況を把握する
2. 理解度を確認する
3. 結果を教材・教育方法の改善へ戻す

# 10. 推奨コンテンツ仕様
結果ごとに2〜3本表示する。記事URLは公開前に既存ブログ棚卸し結果から確定する。

### 現時点の候補
**体系化不足型**
- 教材化は学習目標から始まる

**教材化不足型**
- 社内資料は、なぜそのままでは教材にならないのか
- PowerPoint研修を教育資産に変える条件

**運用不足型**
- 既存の運用・担当者依存・教育資産管理系記事から選定

**改善不足型**
- 教育効果を「受講した」で終わらせない

# 13. 技術アーキテクチャ
## 独立アプリ
コンテキストAI本体とは別リポジトリ／別デプロイ。

- Repo: `educational-asset-diagnosis`
- Hosting: Netlify
- Frontend: Bolt.newで生成、React + TypeScript推奨
- DB: 診断専用Supabase（保存する場合）
- Analytics: GA4
- Domain: サブドメイン推奨

候補:
- diagnosis.adop-context.jp
- check.adop-context.jp

## セキュリティ
- コンテキストAI本番Supabaseへ接続しない
- Service Role Keyをフロントに置かない
- 匿名insertを許可する場合は専用テーブル・最小権限
- 自由記述欄はv0.1では持たない
- 個人情報を診断回答と一緒に保存しない
