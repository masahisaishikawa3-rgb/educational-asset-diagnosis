## v0.1受入チェックリスト（元仕様に基づく）

### 体験と順序

- [ ] Landing → 12問 → Level → 4軸/ボトルネック → 処方箋 → 推奨記事 → CTAの順になっている。
- [ ] 診断完了まで個人情報入力がない。
- [ ] 製品導線は結果提示後に初めて現れる。
- [ ] 結果画面の情報優先順位を崩していない。
- [ ] CTAが診断価値より先行していない。

### 質問

- [ ] 全12問を進められる。
- [ ] 進捗バーと `現在問 / 12` がある。
- [ ] 回答後は自動遷移せず「次へ」で進む。
- [ ] 前問に戻って回答を変更できる。
- [ ] 1〜4点や回答の良し悪しをユーザーに見せない。

### 結果

- [ ] `LEVEL + 名称 + 一言説明` が主役になっている。
- [ ] 48点中の点数が主役になっていない。
- [ ] 4軸を横棒グラフで表示している。
- [ ] 最大ボトルネックが明確で、同点時は補足がある。
- [ ] 処方箋は3項目で、各項目は見出し + 1〜2文になっている。
- [ ] 推奨記事は基本2本、最大3本で、選定理由が1行ある。
- [ ] Primary CTAは「自社資料で教育資産化を試す」を主語にしている。

### 表現・レスポンシブ

- [ ] 低スコアを赤・黄・緑の優劣表現にしていない。
- [ ] Levelを評価・序列ではなく現在地として表現している。
- [ ] 落ち着いたB2Bの現在地確認として見える。
- [ ] デスクトップのQuestionは中央1カラムで、本文幅を広げすぎていない。
- [ ] モバイルは完全1カラムで、CTAは横幅100%。
- [ ] モバイルで情報や文字サイズを削っていない。

### 障害と計測

- [ ] config load errorとresult calculation errorを扱える。
- [ ] analytics errorで画面が停止しない。
- [ ] DB保存エラーで結果表示が停止しない。
- [ ] 仕様記載の7イベントが発火する。
- [ ] URLにスコアを露出していない。
- [ ] DB保存を結果表示の前提にしていない。
- [ ] コンテキストAI本体DBとは完全分離されている。
- [ ] 主要ロジックにユニットテストがある。

### 公開前検証

- [ ] 最低10〜20パターンを手動入力する。
- [ ] 全1点 → Level 1、全4点 → Level 5を確認する。
- [ ] A/B/C/Dのみ低いケースを確認する。
- [ ] A/B同点、B/C同点で優先規則を確認する。
- [ ] 境界19/20、27/28、35/36、42/43を確認する。
- [ ] 5〜10人程度で質問理解、結果納得感、推奨記事の有用性を確認する。

## Codexの判断境界

- 未決事項はユーザーまたは後続仕様の確認なしに確定しない。
- UIの仮実装が必要な場合、仮データはmock/fixtureとして隔離する。
- 原文の「案」「候補」「してもよい」「必要に応じて」は確定採用を意味しない。
- 原文の例示文言や数値を、明記のない全ケースへ展開しない。
