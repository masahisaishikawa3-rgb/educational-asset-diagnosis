# 教育資産化診断｜UI/UX・レスポンシブ要件（Codex引き渡し）

## 文書情報

- 参照元: `docs/EDUCATIONAL_ASSET_DIAGNOSIS_UI_DESIGN_v0.1.md` の3、10、11、16章

## 確定事項

### 全体トーン

- 白〜淡いオフホワイト背景。
- 本文は黒〜濃紺／グラファイト系。
- アクセントは1色。
- グラデーションは使わない。
- 過度なカード乱用を避ける。
- ゲーミフィケーションは不要。
- 「健康診断」「企業成熟度診断」に近い落ち着いた体験にする。

### 文字とスコア表現

- H1は大きくするが誇張しない。
- 本文は16px前後を基準にする。
- 補助テキストも小さくしすぎない。
- Level数字だけを極端に巨大化しない。
- 赤・黄・緑でスコアの優劣を表現しない。
- 同一アクセント色の濃淡、または無彩色 + 1色を使う。
- accessibilityを優先する。

### 質問UI

- デスクトップでも本文幅を広げすぎない。
- 選択肢全体をクリック可能なカードにする。
- 回答選択後に自動遷移しない。
- 進捗バーと現在問数を併記する。
- 回答の良し悪しを色で示さない。

### Desktop

- 最大幅は720〜860px程度。
- Questionは中央1カラム。
- Resultは必要に応じて2カラム可。
  - 左: Level / Type
  - 右: 4軸

### Mobile

- 完全1カラム。
- 選択肢は縦積み。
- CTAは横幅100%。
- 質問画面の下部CTAはstickyにしてもよい。
- 質問と4回答が1画面に収まらなくてもよく、収めるために文字サイズを削らない。
- 横棒グラフはラベルを上、バーを下にしてもよい。
- 結果ページが長くなっても情報を削らない。

## デザインレビューの確認項目

1. 「診断アプリ」ではなく「B2Bの現在地確認」に見えるか。
2. LandingからコンテキストAIの印象が出すぎていないか。
3. 12問を答える心理的負担が低いか。
4. Levelが評価・序列ではなく現在地として読めるか。
5. ボトルネックの納得感が最も強く見えるか。
6. 結果画面が営業ページ化していないか。
7. 推奨記事が処方箋として機能しているか。
8. 最後のCTAで初めて製品へつながる構造か。
9. モバイルでも本文が読みやすいか。
10. 低スコアが「悪い会社」という印象を与えないか。

## 未決事項

- アクセント色の具体的なカラーコード。
- フォントファミリー、ウェイト、厳密なタイポグラフィスケール。
- spacing、角丸、影、アイコン等のデザイントークン。
- ブレークポイントの数値。
- アニメーションの対象、時間、イージング（「控えめ」はShould）。
- sticky CTAを実際に採用するか。
- Resultを1カラム／2カラムのどちらにするか。
- WCAG等の準拠水準。
